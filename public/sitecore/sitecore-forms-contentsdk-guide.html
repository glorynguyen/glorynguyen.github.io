Sitecore Forms +

A complete reference for integrating Sitecore AI Forms with a Next.js application using the Content SDK — from CMS authoring through to frontend component registration.

0
Which path are you on?
The integration model differs by Sitecore platform
✦ Recommended
XM Cloud / Sitecore AI
Use the built-in Form component from the Content SDK. Forms are authored in the AI Forms Builder and delivered via webhook. No session cookies required.
@sitecore-content-sdk/nextjs
Legacy
Sitecore XP + JSS 22.x
Uses the sitecore-jss-react-forms package. Requires REST Layout Service, active SSL, and SSR on every route that shows a form.
@sitecore-jss/sitecore-jss-react-forms
ℹ This guide focuses on the Content SDK + XM Cloud path, which is the current recommended approach for all new projects. The XP/JSS path is covered separately in Section 6.
1
Prerequisites
Verify your environment before starting
  • ▸ Node.js LTS installed on your machine
  • ▸ Access to a Sitecore AI / XM Cloud environment (project + environment created via Deploy app)
  • ▸ JSS version 21.6.0 or later — this is when XM Cloud Forms support via BYOC was added
  • ▸ Content SDK 1.0+ (or JSS 22.6+ if still on JSS)
  • ▸ Advanced User or Admin role in Sitecore AI to create and edit forms
  • ✓ Your Next.js app bootstrapped from a Content SDK starter template
  • ✓ SITECORE_EDGE_CONTEXT_ID set in your .env.local
⚠ Forms on Pages requires JSS 21.6+. If your app is on an older version, you must upgrade before following this guide. See the Sitecore upgrade guide for step-by-step instructions.
2
Environment Variables
Connect your Next.js app to Sitecore AI

In the Deploy app, open your environment → Developer settings tab → select your site → set Context to Preview → copy the environment variables code block.

.env.local 
# Required — from Sitecore AI Deploy app → Developer settings
SITECORE_EDGE_CONTEXT_ID=your-preview-context-id-here
NEXT_PUBLIC_DEFAULT_SITE_NAME=your-site-name
NEXT_PUBLIC_DEFAULT_LANGUAGE=en

# Required for editing / Page Builder preview
SITECORE_EDITING_SECRET=your-editing-secret

# Needed if form webhooks aren't resolving in Vercel
# Ensure SITECORE_EDGE_CONTEXT_ID is also set there
NEXT_PUBLIC_SITECORE_EDGE_CONTEXT_ID=your-preview-context-id-here
⚠ Webhook tip from docs: If you experience issues with Forms webhooks, ensure SITECORE_EDGE_CONTEXT_ID is set as an environment variable in your frontend platform (e.g. Vercel). This is the most common cause of webhook failures.
Variable Purpose Where to find it
SITECORE_EDGE_CONTEXT_ID Server-side context ID for Edge GraphQL Deploy app → Developer settings → Context ID
NEXT_PUBLIC_SITECORE_EDGE_CONTEXT_ID Client-side context ID (exposes secret — use carefully) Same value as above
NEXT_PUBLIC_DEFAULT_SITE_NAME Site name used for content resolution Deploy app → Developer settings → Site dropdown
SITECORE_EDITING_SECRET Required for Page Builder editing mode Deploy app → Developer settings
3
Author the Form in Sitecore AI
Design → Build → Webhook → Activate

Before any frontend code, the form must be created and activated in the Sitecore AI Forms Builder. Forms send data to third-party systems via webhooks — not directly to your Next.js app.

1
Create the form
In Sitecore AI, navigate to Design → Forms → Create form. Start from a blank form or choose a template from the library.
2
Design your fields
Drag fields from the left pane onto the canvas. Configure field keys, validation, and styling. Avoid spaces or special characters in field keys — these cause webhook mismatches.
⚠ Field naming matters. Inconsistent field keys are the leading cause of negative webhook responses (isSuccessful: false). Use consistent camelCase or snake_case naming.
3
Configure a webhook
Go to Settings → Choose webhook → Manage webhooks → Add. Webhooks define where form submission data is sent (your API, CRM, Connect, Zapier, etc.).
Auth TypeWhen to use
OAuth 2Production APIs with token-based auth
API KeySimple third-party integrations
BasicInternal endpoints behind basic auth
No authenticationNot recommended for production
ℹ Test your webhook before activating. Click Test webhook, submit the form, and inspect the payload in the Test Form Submission dialog. Test submissions include "test": true so you can filter them from real data.
4
Activate the form
Only activated forms are available in the Page Builder. Click Activate — the form now appears under the Components → Forms section in Pages.
✓ Once activated, authors can drag the form onto any page in the Page Builder without any additional developer work.
4
Enable Forms in Page Builder
Configure placeholder access in Content Editor

For content authors to insert a form rendering into a page placeholder, the Form rendering must be explicitly allowed. This is a one-time configuration step.

1
Add to Available Renderings
In Content Editor, navigate to:
/sitecore/content/<site>/Presentation/Available Renderings
Add the Form rendering if not already present:
Rendering path
/sitecore/layout/Renderings/Feature/JSS Experience Accelerator/Forms/Form

Component ID: 62DD1639-9F28-4040-8738-C886480B2127
2
Allow the Form in placeholder restrictions
If placeholder restrictions are configured, the Form rendering must be in the allowed list. Navigate to:
/sitecore/content/<site>/Presentation/Placeholder Settings/headless-main
In the Allowed Controls field, add the same Form rendering path shown above.
ℹ Note: If the Allowed Controls field is empty, the placeholder has no restrictions and all available renderings are permitted. You only need this step if restrictions are explicitly configured.

1
Register the Form component in your component map Key step
Open .sitecore/component-map.ts and add the built-in Form import alongside the other built-in components:
.sitecore/component-map.ts
// Built-in components — keep these as-is
import { BYOCWrapper, FEaaSWrapper } from '@sitecore-content-sdk/nextjs';
import { Form } from '@sitecore-content-sdk/nextjs'; // ← built-in Form

// Your own components
import * as CdpPageView from 'src/components/CdpPageView';
import * as Title from 'src/components/Title';
// ...other components

export const componentMap = new Map<string, NextjsJssComponent>([
  ['BYOCWrapper', BYOCWrapper],
  ['FEaaSWrapper', FEaaSWrapper],
  ['Form', Form],        // ← register it here — name must match Sitecore rendering name
  ['CdpPageView', CdpPageView],
  ['Title', Title],
]);

export default componentMap;
✓ That's all the dev work needed for native Sitecore AI forms. The built-in Form component handles rendering, submission routing, and webhook delivery automatically.
2
Wire up SitecoreProvider with the component map
The SitecoreProvider must receive both componentMap and page props. For App Router (dual maps), use the client-safe map in providers:
src/Providers.tsx — client component
'use client';
import { SitecoreProvider } from '@sitecore-content-sdk/nextjs';
import components from '.sitecore/component-map.client'; // client-safe map
import scConfig from 'sitecore.config';

export default function Providers({ children, page }) {
  return (
    <SitecoreProvider
      api={scConfig.api}
      componentMap={components}
      page={page}
    >
      {children}
    </SitecoreProvider>
  );
}
src/Layout.tsx — server component
import { AppPlaceholder, Page } from '@sitecore-content-sdk/nextjs';
import componentMap from '.sitecore/component-map'; // full map (server)

export default function Layout({ page }: { page: Page }) {
  const route = page.layout.sitecore.route;
  return (
    <main>
      {route && (
        <AppPlaceholder
          page={page}
          componentMap={componentMap}
          name="headless-main"
          rendering={route}
        />
      )}
    </main>
  );
}
src/pages/_app.tsx (Pages Router)
import { SitecoreProvider } from '@sitecore-content-sdk/nextjs';
import componentMap from '.sitecore/component-map'; // single map
import scConfig from 'sitecore.config';

export default function App({ Component, pageProps }) {
  const { page, componentProps } = pageProps;
  return (
    <SitecoreProvider
      api={scConfig.api}
      componentMap={componentMap}
      page={page}
    >
      <Component {...pageProps} />
    </SitecoreProvider>
  );
}
3
Regenerate the component map
After updating component-map.ts, regenerate it if using automatic map generation:
terminal
# Regenerate once
npm run sitecore-tools:generate-map

# Or watch for changes during dev
npm run sitecore-tools:generate-map:watch
ℹ The Content SDK auto-generates the map on npm run build and npm run dev by default. Manual regeneration is only needed if you've changed the map file and want to pick up changes without restarting.
4
Verify the sitecore.config.ts
Ensure your configuration file is correctly pointing to the edge endpoint via the Context ID:
sitecore.config.ts
import { defineConfig } from '@sitecore-content-sdk/nextjs';

export default defineConfig({
  // These values are read from environment variables automatically
  // SITECORE_EDGE_CONTEXT_ID → api.edge.contextId
  // NEXT_PUBLIC_DEFAULT_SITE_NAME → defaultSite
  // NEXT_PUBLIC_DEFAULT_LANGUAGE → defaultLanguage
  // SITECORE_EDITING_SECRET → editingSecret

  defaultLanguage: 'en',

  // Optional: disable personalization in local dev
  personalize: {
    enabled: false,
  },
});
6
Verify the Integration
End-to-end test checklist
1
Start the app in connected mode
terminal
npm run dev
Open http://localhost:3000. Your site should connect to the Sitecore AI preview endpoint via the Context ID.
2
Add the form to a page in Page Builder
In Sitecore AI → Pages, open a page. In the left-hand pane → Components → Forms, drag your activated form onto the page. It should render immediately in preview.
3
Submit the form and verify the webhook
Fill in and submit the form on your local site. Then in Sitecore AI Forms → your form → Settings → Test webhook, confirm the payload was received. Look for "test": false in a real submission.
⚠ Negative webhook response (isSuccessful: false) means XM Cloud sent the payload successfully but the endpoint rejected it — typically due to field key mismatches or validation errors on the receiving API. Compare field keys with what your webhook endpoint expects.

Sitecore XP + JSS 22.x — Legacy Path
For existing XP projects not yet on XM Cloud
ℹ Skip this section if you are on XM Cloud / Sitecore AI. This path uses the older sitecore-jss-react-forms package.
RequirementDetail
SSL or disabled secure cookiesForms use session cookies — SSL must be enabled or secure cookies disabled in Sitecore
REST Layout ServiceGraphQL Edge cannot be used with JSS forms — must use REST
SSR onlyEvery route showing a form must use getServerSideProps — SSG is not supported
Rendering Contents ResolverSet to Sitecore Forms Resolver on the Form rendering item in Sitecore
Install packages
npm install @sitecore-jss/sitecore-jss-forms @sitecore-jss/sitecore-jss-react-forms
src/components/JssNextForm.tsx
import { Form } from '@sitecore-jss/sitecore-jss-react-forms';
import React from 'react';
import { NextRouter, withRouter } from 'next/router';
import { sitecoreApiKey } from 'temp/config';

const JssNextForm = ({ fields, router }: { fields: any; router: NextRouter }) => (
  <Form
    language={router.locale}
    form={fields}
    sitecoreApiHost={''}  {/* must be empty string — NOT the actual host */}
    sitecoreApiKey={sitecoreApiKey}
    onRedirect={(url) => router.push(url)}
  />
);

export default withRouter(JssNextForm);
! Critical: sitecoreApiHost must be set to an empty string '', not the actual Sitecore API host. Using the real host bypasses the Next.js proxy rewrite and causes CORS errors.
next.config.base.js — proxy rewrite
// Add to connected mode rewrites to prevent CORS and 404s
{
  source: '/api/jss/:path*',
  destination: `${jssConfig.sitecoreApiHost}/api/jss/:path*`
}
